# Parallel wave

Read after the user picks parallel for the wave. Steps 9 to 14 of SKILL.md still run; this file replaces the `anomaly:build` call per ticket in step 9. [O44, AC-19]

1. Checklist, one line per ticket: `<NN-slug> | touches: <paths> | par`, or `| seq: <reason>`. A ticket is `par` only when all hold: its touches share no path with another `par` ticket; no `seams.md` owner is edited by two of them; it is medium or larger (size from the ticket); at most one `par` ticket needs the `ui_check` port, so one browser run at a time. Each other ticket is `seq`: `anomaly:build` runs it after the parallel close. Fewer than two `par`: say so and run the wave sequentially, with no second question. [P1, P2, P17, N7, AC-19]
2. Shared owner: two `par` tickets that need one new or changed helper get a prep branch. The `implementer` port builds it off the integration tip, and it merges first through build's Shared close. The agents start from the new tip. [N8]
3. Worktrees: one plain worktree per `par` ticket, `git -C <main> worktree add <path> -b <ticket branch> <integration tip>`. `<path>` is beside `<main>`, named `<repo name>-<NN-slug>`; the branch comes from the `branch` port. The Agent tool's `isolation` option is refused from a worktree session, so it is not used. [P5]
4. Dispatch: one `implementer` agent per `par` ticket, all calls in one message, model `model implement`. Absolute paths only: the ticket, the unit folder, its worktree, build's BRIEFS.md and WORKTREE.md. Each agent does build's Start, Red first and Implement for its ticket alone and stops at the branch tip with its touched tests green; review, merge and push stay here. [P4, AC-22]
5. Close in frontier order, one branch at a time: build's Shared close with `<wt>` as the checkout. The next branch starts its close after the previous merge, and takes the new tip through build's conflict round. A stop of build stops the wave. [AC-22]
6. Right after a merge, remove that ticket's worktree with `git -C <main> worktree remove <path>`, before build's `git branch -d`: git refuses to delete a branch that is checked out. A locked folder: retry once at the end of the wave, then print its path. After the last close, `git worktree list` shows no worktree of the wave. [P18, N11]
7. Then push, CI watch and report as in steps 10 to 13 of SKILL.md.
