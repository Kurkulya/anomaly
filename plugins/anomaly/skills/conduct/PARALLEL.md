# Parallel wave

Read after the user picks parallel for the wave. Steps 9 to 14 of SKILL.md still run; this file replaces the `anomaly:build` call per ticket in step 9. [O44, AC-19]

1. Checklist, one line per ticket: `<NN-slug> | touches: <paths> | par`, or `| seq: <reason>`. A ticket is `par` only when all hold: its touches share no path with another `par` ticket; no `seams.md` owner is edited by two of them; it is medium or larger (size from the ticket); at most one `par` ticket needs the `ui_check` port, so one browser run at a time. Each other ticket is `seq`: `anomaly:build` runs it after the parallel close. Fewer than two `par`: say so and run the wave sequentially, with no second question. [P1, P2, P17, N7, AC-19]
2. Shared owner: two `par` tickets that need one new or changed helper get a prep branch. It opens with `ticket adhoc`, runs build's light path through the `implementer` port, and merges first. The agents start from the new tip. [N8]
3. Worktrees: per `par` ticket, one plain `git -C <main> worktree add <path> -b <ticket branch> <integration tip>`. `<path>` is beside `<main>`, named `<repo name>-<NN-slug>`; the branch comes from the `branch` port. The Agent tool's `isolation` option is refused from a worktree session, so it is not used. A ticket branch or worktree left by a stopped wave is reused, not made again. Then `command install` from `ports` once in each worktree. [P5]
4. Red first, done here: build's Start steps for each ticket (`ticket set-status in-progress`), then one message with one `test_writer` dispatch per `par` ticket, with its worktree, absolute paths and build's TEST-WRITER.md. Then in each worktree: commit the red test alone, `ticket red`. [P4, AC-22]
5. Implement: one message with one `implementer` agent per `par` ticket, model `model implement`, build's BRIEFS.md filled with the test path, WORKTREE.md passed on, absolute paths only. The agents implement only; review, merge and push stay here. [P4, AC-22]
6. Close in frontier order, one branch at a time. When an agent stops, remove its worktree: `git -C <main> worktree remove <path>`. A locked folder: retry once at the end of the wave, then print its path. Then `git -C <wt> switch <ticket branch>` and run build's Shared close unchanged with `<wt>` as the checkout: verify runs on the ticket tip, the merge switches back to the integration branch. In a conflict round, tell the same agent by SendMessage that `<wt>` is its checkout. A stop of build stops the wave. After the last close, `git -C <main> worktree list` shows no worktree of the wave. [P18, N11, AC-22]
7. Push after each merge, as in step 10 of SKILL.md; CI watch and report as in steps 11 to 13.
